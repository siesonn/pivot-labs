## Adding a tool

1. Make a folder in `tools/` named for the tool, for example `tools/learning-solutions-guide/`.
2. Put the tool's `index.html`, and any script files it needs, in that folder.
3. Link the shared stylesheet before the page's own styles: `<link rel="stylesheet" href="../../assets/css/pivot-labs.css">`. It brings in the fonts, colors, header, buttons, and form styles. Add the three browser-tab icon `<link>` tags after `</title>` (see "Brand" below). Add the share preview tags (see "Share previews" below). Copy the header from another tool page, including its `<nav class="site-nav">` menu, which marks Tools as the current section with `aria-current="page"`.
4. Add the tool to `tools/index.html` (the All tools page), under the category that matches what the leader is trying to do: its name as a link and one short line about what it's for. Add a new category group only when it has a tool to show. The home page has no tool list of its own, so this is the only list to keep.
5. Decide which situation (home page tile) it belongs to, and add it there in `assets/js/starters.js` (see below). A tool doesn't have to be on a tile, but most should be. Then update the home page: that tile's label ("2 tools · 2 guides") and the count line above the tiles ("There are 10 tools and 7 visual guides so far"). See "What the tile labels say" below.
6. Put the shared footer right after `</main>`. Copy it from any other tool page (for example `tools/delegation-planner/index.html`, the `<footer class="tool-footer">` block). It has a "Related tools" box with two links, a "Did this help?" feedback link, and a few page links. Choose related tools that are true neighbors: a tool someone would naturally use right before or after this one, each with a short line saying why. Use `class="tool-footer wide"` on a page whose content is 1440 px wide (the Eisenhower Matrix and Team Development Map). Then add the new tool as a related link on the one or two existing tools it is closest to, so the link goes both ways. The footer does not print and is hidden in the screenshot view (the styles are in the shared stylesheet).

Add to the shared stylesheet only what more than one page will use. Styles for one page stay on that page.

## Home page tiles and Find pages

Each tile on the home page is written in the leader's words ("Something keeps going wrong"). It is a plain link. Four tiles open a Find page, a page of their own that asks one to three questions and suggests a tool, says why it fits, shows the answers the suggestion rests on, and lists the other tools. Two tiles ("I have a decision to make" and "Something's weighing on me") go straight to their tool, because only one tool fits. "I have a decision to make" will become a Find page when the Role Risk Map is built. "I have a conversation to prepare for" asks "Who's the conversation with?" (someone I lead, my manager or senior leaders, or I'm not sure). "I need help with my team" starts with "Is this about one person or the whole team?" (one person, the whole team, or I'm not sure). The whole team leads to "People aren't sure who owns what" and the Role Clarity Builder; the other two show the questions below. On that page, the "I want to help someone grow" answer asks "Where are you starting from?" with four answers: a task in mind leads to the Team Development Map, ideas to share lead to the Feedback Conversation Planner, and "we haven't talked about it yet" or "I'm not sure" lead to the Coaching Approach Picker.

The tiles are in `index.html` (one `<li class="tile">` each: a picture, the title, a line, and a label such as "2 tools · 2 guides"). Each picture is a small inline SVG drawn in the site's colors and shapes (the Eisenhower grid, the Skill and will grid, a fishbone, a speech-bubble pair, a fork, the emotion wheel), marked `aria-hidden` because the title says what the tile is. Their questions and routing are in `assets/js/starters.js`, shown on the Find pages.

Rules that keep the page from needing a redesign as tools are added:

- **Eight tiles at most.** A new tool joins an existing situation as an answer before it gets a tile of its own.
- **Five answers per question at most, plus "I'm not sure."** Past that, add a question in front that splits the answers, and show the later questions with `showIf`.
- **One fitting tool means a link straight to the tool, not a question.** When a second tool fits that situation, add a Find page.
- **The same answers always give the same suggestion,** whoever the person is. Answers describe the situation, never the person.
- **A tile shows only when it has a live tool.** Planned cards and where future tools fit are in the project's tool roadmap.

**What the tile labels say (since November 20, 2026).** Each label says what is behind the tile, so six tiles don't read as six things: "2 tools · 2 guides" (too much on my plate), "5 tools · 4 guides" (team), "2 tools · 1 guide" (conversation), "2 tools · 2 guides" (keeps going wrong), "Opens a tool" (decision), "Opens a tool · 1 guide" (weighing on me). A tile mentions guides only when it has one. Guides are counted through the tools: a tile counts each visual guide that belongs to one of its tools. The two tiles that open a tool directly keep "Opens a tool," because it says they skip the questions. The question count lives in each Find page's intro ("Answer one question"). The intro above the tiles ends with a count line: "There are 10 tools and 7 visual guides so far, with more on the way." Update the labels and the count line whenever a tool or guide is added.

To add a tool to a situation: add the tool to `TOOLS` in `assets/js/starters.js`, add it to the situation's `options` with a one-line `bestFor`, add an answer that leads to it, and return it from `suggest()` with a "why it fits" reason. To add a tile: copy a `<li class="tile">` in `index.html`, draw or reuse a picture, and add a matching entry to `STARTERS` in `assets/js/starters.js` and a Find page (below).

### Find pages

Each situation with questions has its own page. To make one: copy `find/too-much-on-my-plate/index.html` into a new folder, change the title, description, `og:` tags (including `og:url`), the heading and intro line, and `data-find` (a key in `STARTERS`). Then point that situation's home page tile at the new page and set its label (what is behind it, for example "2 tools · 1 guide"). The page's questions run from `assets/js/starters.js`. The "Not quite your situation?" line at the bottom stays.

## Adding a guided planner

Guided planners (for example the Executive Ask Builder and the Role Clarity Builder) reuse the Delegation Planner's setup. The engine adds one speaking tip per step after the first typed field ("tap the microphone on your keyboard"); it shows only on touch screens (`.voice-tip`, `pointer: coarse`). The Eisenhower Matrix and Team Development Map are standalone pages and do not have it. For fields the engine doesn't have, use a `custom` field: the Root Cause Finder's numbered why chain and fishbone areas show how, and the Role Clarity Builder's repeating rows (add, remove, and a limit) show another.

1. Copy `tools/delegation-planner/index.html` as a starting point. Keep `class="planner-page"` on `<body>` and the element ids the engine uses (listed at the top of `assets/js/guided-planner.js`).
2. Write a `content.js` for the new tool: its steps, questions, suggestions, and how to build the finished brief. Set `finishLabel` if the last button should say something other than "Review my brief."
3. Load `../../assets/js/guided-planner.js`, then `content.js`, then call `GuidedPlanner.create(...)` with the tool's content.

## Adding a situation picker

The situation picker suggests one option from a few questions and says why it fits. The leader can always choose another. The Find pages, the Feedback Conversation Planner, the Root Cause Finder, the Coaching Approach Picker, and the Decision Approach Picker use it.

1. Load `../../assets/js/situation-picker.js` and call `SituationPicker.create(...)` with the questions, the options, and a `suggest(answers)` rule. The same answers must always give the same suggestion, whoever the person is.
2. On its own page, call `picker.mount(container, options)`. Options with an `href` become links to that page or tool. An option can also carry `guide: { title, href }` for its visual guide: the suggestion card then adds "Want the picture first? See the visual guide," and "Other options" adds "Visual guide: (title)", both opening in a new tab. The Find pages get this from the `guide` on each tool in `TOOLS` (`assets/js/starters.js`). Optional settings: `headingLevel` (3 when the picker sits under a page's h2), `showAnswers` (adds "Based on your answer:" with the answers given), and `changeInActions` (puts "Change my answers" beside the main button).
3. Inside a guided planner, put `picker.questions` in one step and `picker.field(...)` in the next. The Feedback Conversation Planner, the Root Cause Finder, and the Coaching Approach Picker show how.

The full setup is described at the top of `assets/js/situation-picker.js`.

Every page has these tags right after its `</title>`: `og:type`, `og:site_name`, `og:title`, `og:description`, `og:url`, `og:image` (with width, height, and alt text), and `twitter:card`. ## Rules learned from real visitors

About 70 percent of visits so far are on phones, so these matter.

- **Link to the home page as the folder, not `index.html`.** Use `../../` (or `../`, or `./`), never `../../index.html`. People arrive at `/`, and a link to `index.html` makes analytics count the home page twice. Other pages (`tools/index.html` and so on) keep `index.html` in their links.
- **Planner pages hold back what sits below the form until it is drawn.** `guided-planner.js` adds `planner-ready` to the body after it draws the first step. Until then the stylesheet hides the Back/Continue row, the "Share the wheel" section, About, and the footer, so nothing visible jumps down when the form appears (this was a layout shift Cloudflare reported). Each planner page has a `<noscript>` rule that keeps Share, About, and the footer visible if script does not run. If you add something new below the form on a planner page, add it to that rule in `pivot-labs.css` and to the `<noscript>` line.
- **Footer links get a thumb-sized tap area on phones** (a rule at the end of `pivot-labs.css`). Links inside a sentence are left alone on purpose.

## How the tools handle entries

The tools run in the browser. There is no server or login, and each page blocks network requests except to Cloudflare Web Analytics, which counts page visits. Entries are not sent anywhere. Entries clear when the page is refreshed or closed.

Tool icons are in each tool's `<li>` in the browse list. A new tool takes one icon the same way (a `tool-icon` span before a `tool-text` span).
- **Browser-tab icon.** The small mark (ribbon on navy) was approved as a favicon on November 14, 2026. It's on the home page and every tool page (added to the tool pages with the brand owner's OK on November 15, 2026). A new tool page takes the same three `<link>` tags after `</title>`, with `../../` in front of each path: `favicon.svg` (`type="image/svg+xml"`), `favicon-32.png` (`sizes="32x32"`), and `apple-touch-icon.png` (as `rel="apple-touch-icon"`).
- New logo variants, palette changes, and program identities need review by the brand owner before release.

## Image buttons open the image, they do not download it
Every shareable image on the site (the seven guides, the Visual guides page, and the Emotion Wheel tool page) is reached with an "Open the image" button that opens the PNG in a new tab, with no `download` attribute. On an iPhone, a download goes to the Files app, where people could not find it; opening the image lets them press and hold it, or use Share or the right-click menu, to save it to Photos, email it, or save it to Files. The same wording works on any phone or computer. Keep it that way for new guides.
